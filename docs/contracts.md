# 模块接口约定（contracts）

> [!IMPORTANT]
> 本文件与 [registry/parameters.yaml](registry/parameters.yaml) 共同构成所有模块规格的约束。任何模块规格与本文件冲突时，以本文件为准；需要修改本文件时，先在 [registry/CHANGELOG.md](registry/CHANGELOG.md) 提出。

## 1. 技术前提

| 项目 | 决定 |
|---|---|
| 游戏引擎 | Godot 4.x，GDScript |
| 运行时数据格式 | JSON（Godot 原生支持）；设计数据以 YAML 编写，构建脚本转换为 JSON |
| 参考实现 | Python 3.9（`sim/` 目录），用于验证可玩性，同时作为 Godot 移植的**黄金标准** |
| 移植验收 | 同一份开局数据 + 同一个随机种子 + 同一串玩家输入，Godot 与 Python 跑 N 天后的全部数值必须一致（浮点误差 ≤ 1e-6） |
| 随机数 | 全部随机数来自一个可设种子的生成器，按"子流"划分（events、world、elections、combat、random_events），保证可复现 |
| 首个可玩版本 | 只做"贝京 1977"剧本 |

> [!NOTE]
> Python 3.9 不支持 `match` 语句和 `X | Y` 类型标注写法，参考实现须避免使用。

## 3. 结算顺序（每个游戏日）

每个游戏日按以下固定顺序执行。每一步只能读取**上一步结束时**的状态，写入通过"效果队列"提交，在该步骤末尾统一应用。

| 步骤 | 模块 | 内容 | 周期 |
|---|---|---|---|
| 1 | M01 | 推进日期；判断今天是否为周/月/季/年结算日 | 每日 |
| 2 | M05 | 应用玩家今天下达的行动（进入执行队列） | 每日 |
| 3 | M09 | 军事行动、战争推进、动员 | 每日 |
| 4 | M07 | 外交谈判进度、危机倒计时 | 每日 |
| 5 | M05 | 执行中的决议推进；完成者结算效果 | 每日 |
| 6 | M06 | AI 部长与 AI 人物行动（越权、告状、要价） | 每周 |
| 7 | M03 | 民调、选民集团支持、议会议程与投票 | 每周 |
| 8 | M09 | 公众安全感、区级安全 | 每周 |
| 9 | M10 | 财政月度收支、外汇 | 每月 |
| 10 | M02 | 各矛盾参数漂移 | 每月 |
| 11 | M04 | 立场偏离结算、党内地位、承诺到期检查 | 每月 |
| 12 | M07/M08 | 外部世界轨道推进与扰动、巴勒斯坦派系 | 每月 |
| 13 | M11 | 区级数值、人口迁移 | 每月 |
| 14 | M13 | 集权度、阻力方阈值检查 | 每月 |
| 15 | M05 | 政治资本月产出 | 每月 |
| 16 | M10 | 增长、通胀、失业 | 每季 |
| 17 | M10/M06/M11 | 预算法案期限、人物年龄与健康、人口结构 | 每年 |
| 18 | M12 | 事件调度：固定事件条件检查 → 随机事件掷骰 → 弹窗队列 | 每日（固定事件），每月（随机事件掷骰日分散到月内各日） |
| 19 | M03 | 大选、不信任投票、组阁（如被触发） | 事件 |
| 20 | M14 | 结束条件检查 | 每日 |

**自动暂停**：步骤18产生需要玩家决策的弹窗时，在当日结算结束后暂停（M01 规格定义暂停规则）。

## 4. 效果（Effect）统一格式

所有模块、事件、行动对状态的修改都表达为"效果"，由效果解释器统一应用。效果的数据格式：

```yaml
- op: add            # add | set | mul | add_modifier | remove_modifier | set_flag | clear_flag | trigger_event | schedule_event | add_relation | change_seat | custom
  target: bloc_support
  key: mizrahi       # scope 为 bloc/party/region 等时必填
  value: -5
  # 可选
  scale: "1 - region_development[negev]/200"   # 表达式，见第5节
  delay_days: 0
  chance: 1.0
```

- 写入后自动按 `range` 夹紧。
- `derived` 类型参数禁止直接写入（解释器报错）。
- `custom` 只允许引用 M01 规格中登记过的处理函数名。

## 5. 条件与表达式

触发条件、概率修正、效果缩放统一使用一个**极小的表达式语言**（M12 规格给出完整语法），示例：

```
alienation[mizrahi] >= 40 and region_development[haifa] < 30
flag("settlers_momentum_high") or months_since(event("E-1977-11")) > 6
0.25 * (1 + (60 - regime_hostility[egypt]) / 100)
```

- 只允许：数字、参数引用、比较、and/or/not、+−×÷、min/max/clamp、flag()、has_modifier()、event_done()、months_since()、character_in_office()、year、era()。
- Python 参考实现与 GDScript 实现各写一个解析器，必须通过同一套表达式测试用例（M12 规格提供）。

各模块规格必须在第2节列出完整的读/写清单；**只有 owner 模块可以在结算步骤中直接写入参数**，其他模块只能产生效果。

| 模块 | 主写参数（owner） | 主要读取 |

| M02 | 宗教现状、兵役豁免、疏离度、历史怨气、国家认同度、土地怨气、定居者动量、民主法治、司法冲突 | 几乎全部 |
| M03 | 盟党满意度、选民集团支持、联合政府席位、选民倾向 | 矛盾参数、经济、安全、承诺 |
| M04 | 党内地位、承诺进度、立场偏离、愿景进度 | 政策状态、行动历史 |

| M08 | 巴勒斯坦敌意、生活水平、派系实力与合法性、起义风险、伊斯兰协会 | 占领政策、军事 |
| M09 | 战备、动员、威慑、公众安全感、战略自满、核计划、国家整合度 | 预算、外部世界 |

## 7. 规格完成的判定（Definition of Done）

一份模块规格只有同时满足以下条件才算完成：
1. 使用 [spec_template.md](spec_template.md) 的全部章节。
2. 所有参数都来自总参数表；新增参数已登记。
3. 每个公式都有初始系数、单位和一个算例。
4. 至少5条**可自动判定**的验收测试（输入状态 → 期望输出）。
5. 通过"实现者审阅"：另一个子代理以只读规格、不看其他资料的方式，确认可以据此写出 Python 实现，"无法实现之处"清单为空。
